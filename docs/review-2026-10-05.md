# 2026-10-05 review and repairs

The final independent Codex Code Review returned **No findings.** All five findings from the preceding review were repaired and checked again. This means no remaining actionable defects were confirmed within the reviewed scope; it does not certify untested external environments.

## Scope

The review inspected the complete working-tree changes and existing call paths for routing, HTTP/CONNECT/SOCKS5, provider lifecycle, management API, CLI, TUI, Web UI, diagnostics, installation, PAC, Docker exports, localization, and development hooks. It used the defect-first `review-agent` contract. The independent reviewer did not edit repository files or delegate the review.

## Confirmed findings repaired

| Finding | Repair and regression coverage |
| --- | --- |
| Multiple processes could open the same Tailscale state directory. | Acquire an exclusive lock before starting tsnet; retain it until the node closes. Child-process tests cover concurrent ownership and release; initialization-failure tests cover cleanup. |
| An in-flight TUI refresh could change the selected outbound and revision behind an open editor. | Keep the editor's configuration snapshot until it closes, preserving revision-conflict protection. Tests cover rule and outbound editors and selection identity during refresh. |
| Signing in after logout/disconnect could hide the new Tailscale login URL. | Clear the stopped flag only after starting login successfully. Tests cover visible login state and preservation of stopped state on failure. |
| A valid zero-millisecond adaptive improvement threshold was replaced with 50 ms. | Preserve zero and test switching with sufficient samples, percentage improvement and repeated observations. |
| Periodic status refresh could discard keyboard focus on a Tailscale sign-in link. | Restore focus using outbound identity and a stable link marker. Tests cover both sign-in links and existing controls. |

Additional fixes from UI/TUI and hook checks preserve cumulative traffic on narrow screens, identify each PAC switch by its destination, retain selected rows during TUI refresh, keep pending outbound actions disabled during polling, explain disabled outbound actions, and hash bundled fonts without exceeding ordinary source-file limits.

## Verification

- Maintainer checks: `mise run check`, `mise run build`, `mise run release`, bounded parser fuzzing, the actual post-edit hook, and `git diff --check` passed.
- The independent final reviewer separately ran all tests with race detection and randomized order, lint, and whitespace checks; all passed.
- Browser checks used the embedded UI with a local fake management backend: English and Traditional Chinese, 390/820/1440 px layouts, traffic grouping and expansion, outbound rule defaults, disabled controls, automatic refresh, retained sign-in focus, PAC notes with Chinese/emoji, accessible switches, and glossary search.
- A real terminal session exercised TUI navigation, language switching, form defaults, cancellation, and hidden management-token behavior. Automated tests cover refresh/editor concurrency.
- Release builds succeeded for Linux and macOS, on amd64 and arm64. Cross-compilation does not prove execution on those platforms.

The browser and TUI checks above were performed by the maintainer. The independent reviewer used source inspection and automated UI contract tests, and did not independently repeat the browser or terminal session.
