Start with the words you see on screen

You do not need to learn every term. Start with Proxy, Outbound, Direct and Bypass, then look up the words you need.

Choosing a connection

Proxy

An app sends its connection through another service. That service connects to the website for it.

In Rillway Set your browser to use Rillway. Only traffic sent through this proxy appears in Connections.

Outbound

The connection method Rillway uses to reach a destination. You can give each one a name.

In Rillway A rule can send GitHub traffic through an outbound named warp.

Direct

Use the network of the machine running Rillway, without a VPN for this connection.

In Rillway On an Ubuntu VM, direct uses the VM network. It still passes through Rillway and appears in Connections. The built-in direct cannot be deleted.

VPN / tunnel

An encrypted connection to another network or service. Its destination determines which network your traffic can reach.

In Rillway Rillway uses VPNs for selected proxy connections. It does not put every app on your machine through a VPN.

Split tunneling

Send different destinations through different connections.

In Rillway Keep company services on your Mac Tailscale connection, and send public websites to Rillway through PAC.

Routing rule

An instruction that matches a domain or IP range and chooses its outbound.

In Rillway Fixed rules are checked before adaptive rules. Within each group, rules are checked from top to bottom. A fixed VPN rule that fails does not silently switch to direct.

Default outbound

The outbound used when no routing rule matches.

In Rillway Choose it under Routing rules. Explicit rules take priority.

Bypass / DIRECT

The app connects without sending that traffic to Rillway.

In Rillway PAC bypass keeps company traffic on your Mac. This traffic does not appear in Rillway; it is different from the direct outbound on Ubuntu.

Adaptive routing

Rillway compares connection success and connection delay, then may choose another allowed outbound for new connections.

In Rillway Enable it yourself and choose candidates. Fixed rules stay first; existing downloads keep their route. It does not automatically download files to test speed.

Names and addresses

Domain / subdomain

The readable name of a website or service. A subdomain is a name within that domain.

In Rillway github.com and api.github.com are different exact matches. A suffix rule for github.com also includes its subdomains.

IP address

A network address used to connect to a device or service. A domain can have more than one IP address.

In Rillway An address such as 192.168.1.20 can identify your VM on the home network.

DNS

Find the IP address for a domain name.

In Rillway Rillway resolves names through the selected outbound. With SOCKS5, use proxy-side DNS to keep domain rules working.

CIDR / IP range

A short way to write a range of IP addresses. The number after the slash specifies the range.

In Rillway 192.168.1.0/24 covers 192.168.1.0 through 192.168.1.255; 192.168.1.20/32 matches one IPv4 address.

IPv4 / IPv6 / dual stack

Two address formats. Dual stack allows either format when the network and outbound support it.

In Rillway IPv4 looks like 192.168.1.20; IPv6 looks like 2001:db8::20. Choose Automatic unless you need to test a specific format.

LAN / private network

The network inside your home or company. Private addresses are not publicly reachable Internet addresses.

In Rillway Allow the IP of your Mac to reach the VM proxy. Keep company domains in the bypass list.

Loopback / localhost

An address that points back to the same machine or network environment.

In Rillway 127.0.0.1 and ::1 point to the current machine. Inside a container, they point to that container, not the Ubuntu host.

Browser and network settings

HTTP Proxy

A proxy format supported by many browsers and applications for web connections.

In Rillway Use the HTTP listener for both HTTP and HTTPS proxy settings. HTTPS uses CONNECT; do not enter the management UI port.

HTTPS CONNECT

The browser asks the proxy to open a connection to a secure website, then carries encrypted HTTPS traffic through it.

In Rillway Rillway can show the destination host but does not decrypt the page path, passwords or content.

SOCKS5

Another proxy format used by browsers and other TCP applications.

In Rillway Rillway supports SOCKS5 TCP. UDP is not supported; enable proxy-side DNS in your app when available.

PAC

A small set of browser or system rules that chooses whether a destination uses a proxy or connects directly.

In Rillway Use the PAC URL from Rillway on your Mac. Add company domains to bypass; public traffic goes to Ubuntu.

Listener / port

The address where Rillway accepts connections. A port number identifies which service to use at that address.

In Rillway Defaults are 17890 for HTTP, 17891 for SOCKS5, 17892 for HTTPS management and 17893 for PAC.

Network service / interface

A network interface connects your device to a network. On macOS, its network service has a name such as Wi-Fi or USB Ethernet.

In Rillway Apply PAC to the network service you use. Rillway selects a service name, not a device number such as en0.

VPN services

Cloudflare WARP

A Cloudflare connection that Rillway can use as another route to public websites.

In Rillway Install the official client on the Rillway host and use Local Proxy mode. A different route may help congestion, but speed depends on the current network.

WARP+ license / Unlimited

Rillway can send your WARP+ license key to the official client and check the account status it reports.

In Rillway Unlimited is the account label reported by the client. It does not prove the proxy is connected or that every website will be faster; verify the outbound separately.

Tailscale / tailnet / MagicDNS

Tailscale connects devices in your private network, called a tailnet. MagicDNS gives those devices readable names.

In Rillway Keep your existing Mac Tailscale for company services. The embedded Rillway Tailscale outbound reaches its tailnet; it does not provide a public Internet exit here.

WireGuard

A VPN connection configured with server addresses and keys. What it can reach depends on the VPN configuration.

In Rillway Rillway reads a WireGuard configuration file and runs its engine inside the binary. Keep the private key file private.

Reading connection status

Download / upload rate

How much data is moving each second. Download is data received from the destination; upload is data sent to it.

In Rillway KiB/s and MiB/s count bytes per second. Quiet or idle connections can show zero without a network problem.

Transferred

The total data sent and received for a connection so far.

In Rillway A large total means more data was transferred. It does not tell you the current speed.

Connect time / ms

How long it took to open a connection. One millisecond is one thousandth of a second.

In Rillway Lower connection time can make starting a request quicker. It does not measure the speed of a whole download.

Connected / verified

Connection status and an actual Internet check answer different questions. A running process alone does not prove traffic can get through.

In Rillway Verify outbound checks an actual connection. A WARP listener marked Not ready means its local proxy is not available.

Destination IP unknown

Rillway could not confirm the destination IP. An upstream proxy may resolve the domain without returning the address it used.

In Rillway Rillway shows unknown rather than guessing. The WARP Local Proxy address is not the website address.

Managing Rillway

Management token

A private sign-in secret for the Rillway control panel and API. Anyone with it can manage the service.

In Rillway Read the token file locally to sign in. Do not share it in screenshots, URLs, logs or Git.

HTTPS / TLS certificate

HTTPS encrypts the management connection. A certificate helps your browser or TUI verify which server it is connecting to.

In Rillway Verify the displayed fingerprint before trusting the default self-signed certificate. This protects management traffic, not every HTTP or SOCKS link.

Daemon / systemd / LaunchAgent

A background program that keeps Rillway running without leaving a terminal open. The operating system starts and stops it.

In Rillway Linux uses systemd; macOS uses your LaunchAgent. Closing the Web UI does not stop the service.

Configuration revision

A number that identifies the configuration currently in use. It helps prevent an older browser tab from overwriting a newer change.

In Rillway If another tab changed settings first, refresh before saving again. The applied time tells you when the version took effect.

Docker Engine / build / container

Docker Engine pulls images. A build creates an image, and a container runs an app using an image. Each can have different proxy settings.

In Rillway Rillway exports settings for these connections. Review and apply them in Docker; generating a file does not change Docker settings.

NO_PROXY

A list of destinations that a compatible app should connect to without its configured proxy.

In Rillway Docker NO_PROXY and browser PAC use different matching rules. Verify company DNS and access inside the container.
